## 产品要求

1. 所有登录用户都可以发布「悬赏」帖子，无需管理员或 Pack 所有者权限；访客可阅读。
2. 规则、奖励和参与方法放在富文本帖子正文里，帖子关联 1–5 个已有的站内 Pack，支持搜索和移除选择。悬赏的说明文字统一为「为站内图包发起悬赏」。编辑区使用留白和简洁行布局，不用一堆卡片、边框或嵌套容器。
3. 使用一个名为「永久」的 Checkbox 控制期限，默认不勾选，新建时显示截止日期时间，必须填写才可保存。主动勾选时隐藏日期选择器，提交 end: null；取消勾选后日期再次必填。不要用两个切换按钮，也不要把未填写日期自动当作永久。日期使用客户端时区编辑并转换为 ISO UTC 提交。
4. Pack 列表的特色标识和筛选名称统一为「悬赏」，不要命名为「悬赏中」。不增加新的排行榜、排名、奖金托管或支付流程。
5. 跳转到悬赏帖的入口放在 Pack 详情页。列表卡片/表格的悬赏标识只表示特色状态，点击 Pack 仍进入 Pack 详情。
6. 四种帖子类型统一去掉编辑页主容器、侧栏和预览区的大边框，保留原来的四个块状类型按钮。侧栏仅显示「温馨提示」和「建议多使用 H2/H3/H4 来组织文章结构，作为分节标题」。删除语言版本说明、截止时间提示、关联图包帮助与空状态提示。日期选择框放在「永久」勾选项前面。

## Pack 详情页横幅

在现有 PackShowcase 主展示区之后、简介和信息的双栏区域之前，加入高度约 40–48px 的紧凑横幅，沿用现有浅色/深色、边框和分区风格。

单条悬赏示意：`悬赏 | 指定难度 FC 挑战 | 永久 | 查看帖子 →`。

- 常态仅展示图标/「悬赏」、帖子标题、期限和跳转提示；不展示发布者、规则正文或大卡片。
- 标题占可伸缩空间，过长省略，桌面可提供完整标题提示；null 期限显示「永久」，限时显示包含年月日、时分的本地化截止时间。
- 点击主体跳转到 `/post/{post_id}`（沿用现有前端帖子详情路由），使用真实链接保证键盘可访问。
- 手机端优先保留「悬赏」、标题和箭头，避免多行撑高横幅；期限空间不足时可简化或收起。
- 通常只有一条悬赏，默认使用后端 bounties[0]。存在多条时添加独立的「另有 X 条」按钮，使用紧凑 Popover/移动端 Sheet 展示其余悬赏的标题、发布者、永久/期限及帖子链接。避免在主体 Link 内嵌套交互按钮。
- 没有有效悬赏时隐藏整个横幅；不添加空状态或历史悬赏面板。
- 横幅属于整个 Pack，切换难度、展开预览工作台时保持关联内容不变。
- 页面停留到悬赏到期时，应更新当前有效项目并刷新 Pack 查询，避免长期显示已经过期的入口；从帖子返回及重新聚焦时使用现有查询刷新机制。

## 已实现的后端接口

- 帖子类型：新增 `4 = 悬赏`，原 0/1/2/3 不变。
- `POST /post` 创建，`PUT /post/:post_id` 编辑：在现有字段之外支持 `pack_ids: number[]`（1–5 个不同的有效站内 Pack ID），`end: null | ISO日期字符串`，`limit: null`。translations 使用 `{language: 'zh'|'en', title, content}` 完整对象，至少一种语言有标题和规则正文。
- `GET /post/:post_id` 新增 `pack_ids`、`linked_packs`、`bounty_closed_at`、`bounty_status`。linked_packs 提供 Pack 标题、艺术家、谱师、封面等回填所需简要字段；bounty_status 为 active/expired/closed，非悬赏为 null。
- `GET /post/type/4` 获取悬赏帖子；`GET /post/forum` 新增 type=4 分组。论坛、帖子详情、个人帖子列表、管理员列表和类型映射都需正确识别新类型。
- `PATCH /post/:post_id/bounty/close` 无请求体：帖主或拥有 posts 权限的管理员可手动结束悬赏，返回 `{data: {post_id, bounty_closed_at, bounty_status: 'closed'}, message}`。重复关闭幂等。
- `GET /pack` 支持 `bounty=1` 筛选有效悬赏，所有列表项新增 `has_bounty: boolean` 和 `bounty_count: number`。沿用推荐等特色筛选的位置和原有排序，可组合其他筛选。同步更新筛选 URL、状态、持久化、重置逻辑和查询键。
- `GET /pack/:pack_id` 新增 has_bounty、bounty_count、bounties。bounties 只含有效悬赏，已按最新发布优先排序；每项包括 post_id/user_id/type/end/bounty_closed_at/bounty_status/created_time/updated_time、translations（仅 title/language）和 user（user_id/user_name/avatar）。无有效悬赏返回 false/0/[]。标题按当前语言选取，缺失时回退另一语言。
- 永久条件为 end === null；限时到期自动失效，不需要前端 PATCH 结束。手动结束后编辑正文、期限不能重新开启。到期但未手动结束的帖子允许改设未来日期或永久，重新生效。
- 已到期的原截止时间可原样保存，以便编辑规则；新设时间必须在未来。悬赏帖子不能切换成其他帖子类型，在编辑 UI 中避免给出无效的类型切换选项。
- 非悬赏帖子不要发送非空 pack_ids，也不要把悬赏的可选截止规则改到征稿流程。
- 输入错误 400、无权操作 403、不存在 404；沿用现有 HTTP 客户端、登录/CSRF、富文本、语言资源和 mutation 错误展示。

## 本次 review 修复要求

1. **将永久期限改为受表单控制的勾选项。** 默认不勾选「永久」，日期时间必填；在日历中清空日期必须保留非永久状态并显示校验错误，不能静默发出 end: null。主动勾选才提交 end: null。Checkbox 支持键盘、关联 Label，补齐中英资源。编辑时根据原 end 是否为 null 回填，手动结束后禁用期限设置并显示「此悬赏已结束」。同步修改表单 schema、提交、草稿保存、恢复与 reset；兼容原有没有永久布尔字段的草稿。避免把受控表单状态和独立的 customBountyDeadlineOverride 同时作为期限模式来源。

2. **手机端能看到帖子状态和期限。** 目前 PostSidebarMetaCard 放在 RichTextToc 的桌面侧栏中，移动端隐藏，抽屉也不包含这些信息。在手机和平板文章标题或作者行附近展示简洁的悬赏摘要：进行中/已到期/已结束，以及永久/具体截止日期时间；手动结束时显示结束状态，避免让已关闭帖子看起来仍能参与。不要依赖桌面侧栏。

3. **正确处理缓存跨越截止时间。** getBountyStatus 目前直接信任缓存中的 active，导致已经过去的 end 仍返回 active。手动结束优先，保留服务端的结束状态；对 active 结合当前时间判定。帖子详情、相关列表和横幅在到期时更新或刷新，不依赖用户主动操作。长截止日期应分段安排定时检查，不能超过 setTimeout 上限就放弃更新。

4. **聚焦刷新包含永久悬赏。** 项目默认 refetchOnWindowFocus: false，现有横幅只在期限到期时失效查询，永久悬赏没有计时器。如果作者或管理员在其他会话关闭或删除悬赏，返回当前页面仍显示旧横幅。为相关帖子、Pack 列表/详情查询覆盖聚焦刷新或实现对应的可见性刷新，返回页面时获取新状态，不要只在自己的 mutation 成功时刷新。不要无理由修改其他业务的全局查询策略。

5. **保留未修改期限的原始精度。** toDatetimeLocalValue 截断到分钟，例如原 end 是 2020-01-01T12:34:56.000Z，提交却变成 12:34:00，导致后端将其视为新的过去时间而返回 400。编辑正文且未变更期限时原样提交原始 ISO end（含秒、毫秒），或者按后端支持的局部更新约定省略 end。新的日期才按本地时间转换 UTC。对于已经到期或手动结束的帖子也要能够保存正文，不强制改为永久或未来日期。

6. **展示确切的截止时分。** 横幅、多条悬赏列表、帖子期限摘要与侧栏目前使用 formatDate，只输出年月日。新建包含本地化日期和时分的显示方式，限时悬赏能够区分当天凌晨与深夜的截止时间。保持横幅紧凑，移动端横幅空间不足可省略期限，但帖子详情摘要必须完整可读。不要改变其他页面只需日期的显示行为。
